# torrent_web_scraper

등록한 TV 프로그램의 새 회차를 토렌트 게시판에서 찾아 Pi의 Transmission에 자동으로 추가하는 개인용 크롤러다. 사이트가 고장나면 Claude(Doctor)가 원인을 진단한다.

```
Linux host (Docker host network)
└─ Docker container  ─  FastAPI + uvicorn (process 1개)
   ├─ Web UI (prod 127.0.0.1:8080, dev 127.0.0.1:8081, 포트는 .env로 변경)
   ├─ 수동 크롤링 실행 (asyncio)
   ├─ Crawler ── Playwright Chromium (--headless=new, ECH) ──→ 토렌트 사이트 3곳
   ├─ Doctor ─── Claude Agent SDK + 전용 진단 도구
   ├─ SQLite (/data/app.db, 호스트 ./data/<env>에 보존)
   └─ Transmission RPC ──→ Pi (주소는 .env의 TRANSMISSION_URL)
```

## 왜 이 구조인가

Pi(Raspbian 10, armv7)에서는 최신 도구를 쓸 수 없다. 그래서 크롤링은 Linux 호스트의 Docker에서 하고 Pi는 Transmission만 맡는다. 국내 SNI 차단 때문에 curl, requests 같은 일반 HTTP 클라이언트는 TLS 단계에서 끊길 수 있다. ECH를 지원하는 Chromium `--headless=new`로 접속한다.

이미지는 `python:3.12.15-slim-bookworm` 위에 멀티 스테이지로 만든다. 빌드 단계에서 uv로 `.venv`를 만들고, 실행 단계에는 `.venv`와 `app/`만 복사한 뒤 `playwright install --with-deps chromium`으로 전체판 Chromium과 그 시스템 라이브러리만 설치한다(`/ms-playwright`). Firefox, WebKit, uv는 넣지 않는다. 크기는 약 1.5GB이고, 대부분 Chromium(약 590MB)과 Doctor가 쓰는 Claude Code 실행 파일이 든 claude-agent-sdk(약 230MB)다. dev와 prod는 같은 Dockerfile을 쓴다. Alpine은 Playwright Chromium이 musl을 지원하지 않아 쓸 수 없다.

## 설치와 실행

1. `.env.example`을 `.env`로 복사하고 값을 채운다(권한 600 권장).

| 키 | 설명 |
|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` | Doctor용 Claude 인증. `ANTHROPIC_API_KEY`로 대신해도 된다(둘 중 하나). |
| `TRANSMISSION_URL` | Pi RPC 주소. 예: `http://192.168.0.10:9091/transmission/rpc` (`/transmission/web/`이 아닌 RPC 경로) |
| `TRANSMISSION_USER`, `TRANSMISSION_PASSWORD` | Transmission RPC 계정 |
| `PROD_PORT`, `DEV_PORT` | 웹 UI 포트(127.0.0.1). 기본 8080, 8081 |

2. `./server.sh prod up`
3. 브라우저에서 `http://127.0.0.1:8080`(`PROD_PORT`)에 접속한다. 인증이 없으므로 웹 서버는 호스트의 루프백 주소에만 바인딩한다.

## 서버 구동

서버는 dev와 prod 두 가지이고, 둘 다 Linux의 Docker 호스트 네트워크에서 돈다. `server.sh`는 이미지를 호스트 네트워크로 빌드하고 컨테이너도 호스트 네트워크에서 실행한다. 두 compose 파일은 컨테이너 DNS를 `8.8.8.8`로 지정한다. 웹 서버는 각각 `127.0.0.1`의 다른 포트에만 바인딩하고, DB도 분리되어 있어 동시에 띄울 수 있다.

| | dev | prod |
|---|---|---|
| 주소 | http://127.0.0.1:8081 (`DEV_PORT`) | http://127.0.0.1:8080 (`PROD_PORT`) |
| compose 파일 | `compose.dev.yaml` (프로젝트 `torrent_web_scraper-dev`) | `compose.yaml` (프로젝트 `torrent_web_scraper`) |
| DB | `./data/dev/app.db` | `./data/prod/app.db` |
| 크롤링 | 모든 실행이 dry-run. Transmission 추가, 다운로드 기록, 사이트 URL 변경, `last_ok_at` 갱신을 하지 않는다 | Transmission에 실제로 추가한다 |
| 코드 반영 | `./app`을 마운트하고 `uvicorn --reload`로 저장 즉시 재시작 | 이미지에 굽는다. 코드를 바꾸면 `up`으로 재빌드 |
| 재부팅 | 자동으로 뜨지 않는다 | `restart: unless-stopped`이라 Docker가 켜지면 자동으로 뜬다 |
| 화면 표시 | 상단에 `DEV · dry-run` 배지, 탭 제목에 `[dev]` | 표시 없음 |

### 명령

```sh
./server.sh <dev|prod> <command>
```

| 명령 | 동작 |
|---|---|
| `up` | 이미지를 빌드하고 백그라운드로 띄운다 |
| `down` | 컨테이너를 내린다. DB는 남는다 |
| `restart` | 컨테이너를 재시작한다(재빌드 없음) |
| `reset` | 내리고 DB를 지운 뒤 다시 띄운다. `app/db.py`의 현재 시드 URL로 새로 시작한다. prod는 `prod`를 입력해야 진행한다 |
| `logs` | 로그를 따라 본다 |
| `ps` | 컨테이너 상태를 본다 |
| `dry-run` | 크롤링을 한 번 실행하고 로그를 출력한다. Transmission 추가와 URL 변경은 하지 않는다 |

새 DB는 기본적으로 수동 실행이다. prod를 `reset`하면 실행 방식도 수동으로 초기화된다. `지금 실행`을 누르면 게시판을 확인하고 새 마그넷을 일시 정지 상태로 등록한다.

### 환경 구분

환경은 `APP_ENV`(`dev` | `prod`) 하나로 정하고, compose 파일이 값을 넣는다. 다른 값이면 앱이 시작하지 않는다. 값이 없으면 `dev`로 본다. 설정이 빠졌을 때 실제 다운로드가 일어나지 않게 하기 위해서다. `app/config.py`가 `APP_ENV`에서 `DRY_RUN`을 정하고, 스케줄러와 `python -m app.scheduler`가 그 값을 따른다. 비밀값은 두 환경이 같은 `.env`를 쓴다.

**Linux 네트워크**: Docker 호스트 네트워크를 사용하므로 컨테이너가 호스트의 네트워크 경로를 따르고, DNS는 compose의 `8.8.8.8` 설정을 따른다. `127.0.0.1` 바인딩을 유지해야 인증이 없는 웹 UI가 외부에 노출되지 않는다. Pi의 Transmission에 닿지 않으면 실행 기록에 `transmission FAIL ... timed out`이 남고 상태가 `partial`이 된다.

## 화면

| 화면 | 내용 |
|---|---|
| 대시보드 `/` | 상태 카드(마지막 실행 결과, 자동·수동 선택, 자동 실행 주기), 지금 실행/실행 중지, 통계, 최근 실행 초기화, Transmission의 현재 다운로드, 앱 DB의 다운로드 이력 |
| 프로그램 `/programs` | 맨 위에서 마그넷 직접 추가. 아래에서 프로그램 등록(이름 + 해상도 720p/1080p 복수 선택, 안 고르면 무관), 해상도 수정, 켜기/끄기, 삭제. 위에 있을수록 먼저 매칭된다 |
| 사이트 `/sites` | 접고 펼칠 수 있는 사이트 추가 양식과 사이트별 카드: URL(새 탭), 켜기/끄기 스위치, 최근 성공, 최근 진단 판정, 진단, 수정, 삭제. 머리 오른쪽에 진단 모델 설정 |
| 실행 상세 `/runs/{id}` | 상태, 시작·소요·매칭·추가, 로그(`FAIL`/`error` 줄 강조) |
| 진단 리포트 `/doctor/{id}` | 판정 카드와 요약, 현재/제안 비교(바뀐 칸 강조)와 [이 설정으로 변경], 근거, 진행 로그(진행 중엔 2초마다 갱신, 끝나면 접힘), 모델과 비용 |

실행 상태는 한국어 배지(원시값은 툴팁)로, 시각은 날짜를 붙여 `10-18 19:23 · 42분 전`처럼(지난해는 `2025-10-18 19:23`) 보인다. 삭제와 사이트 설정 변경은 확인 창을 거친다. 진단(최대 $1)은 누르면 바로 시작한다.

스타일은 빌드 없는 CSS 파일 하나(`app/static/app.css`, `/static`으로 제공)다. 다크 모드는 OS 설정을 따른다. 글꼴은 Pretendard를 jsDelivr CDN에서 불러오고, 못 불러오면 시스템 글꼴(Apple SD Gothic Neo 등)로 대체된다. JS는 진단 화면의 htmx와 확인 창뿐이다. 휴대폰 폭(720px 이하)에서는 nav가 둘째 줄로 내려가고 카드와 표가 한 열로 쌓인다.

### 사이트 추가와 삭제

- **사이트 추가**를 누르면 접혀 있던 입력 양식이 펼쳐진다. 이름, 사이트 URL, 게시판 경로(한 줄에 하나), 게시판마다 읽을 페이지 수를 입력하고 **사이트 추가**를 누른다. 새 사이트는 꺼진 상태로 저장되므로 설정을 확인한 뒤 켜기 스위치를 사용한다.
- 각 사이트 카드에서 **수정**으로 주소와 게시판 설정을 바꾸고, 오른쪽 끝의 **삭제**로 사이트를 삭제할 수 있다. 삭제할 때 해당 사이트의 진단 기록도 삭제되며 다운로드 이력은 유지된다. 크롤링이나 해당 사이트의 진단이 실행 중일 때는 삭제할 수 없다.

### 다운로드와 이력

- **다운로드**는 Transmission RPC의 현재 목록을 직접 조회한다. 이 앱에서 추가하지 않은 Transmission 항목도 표시한다. 상태를 누르면 `.env`의 RPC 주소에서 유도한 Transmission 웹 화면이 새 탭으로 열린다. 진행 중인 항목은 **중지**, 중지된 항목은 **재실행**할 수 있다. Transmission 연결에 실패하면 목록 대신 확인 불가 메시지가 나온다.
- **다운로드 이력**은 이 앱이 DB에 기록한 해시·프로그램·회차·사이트를 보여 준다. Transmission에서 항목을 지워도 DB 이력은 남는다. **이력 비우기**는 화면에서만 숨기며 중복 방지 기록과 Transmission 항목·파일은 보존한다. **숨긴 이력 표시**로 다시 볼 수 있다.
- 이력에서 **Transmission에 없음**인 항목은 **DB 삭제**가 가능하다. 서버가 삭제 직전에 Transmission을 다시 조회하며, 연결 실패나 항목 존재 시 삭제하지 않는다. 삭제하면 DB의 해시·회차 중복 방지 기록도 없어져 같은 회차를 나중에 다시 추가할 수 있다. Transmission 항목·파일은 삭제하지 않는다.
- **최근 실행 초기화**는 완료된 실행을 화면에서 숨긴다. 상세 로그는 DB에 남는다. 실행 중인 항목은 완료 후 초기화할 수 있다.
- 프로그램 페이지 상단의 **마그넷 직접 추가**는 프로그램 매칭 없이 Transmission에 일시 정지 상태로 추가하고 앱 이력에도 기록한다. 대시보드에서 재실행을 눌러야 다운로드가 시작된다. 40자리 16진수 또는 32자리 Base32 BTIH 해시를 받는다. 이미 Transmission에 있는 항목은 중복으로 안내한다. dev 환경에서는 실제 다운로드를 추가하지 않는다.

## 크롤 규칙

- 켜진 사이트의 게시판마다 1~N쪽(`?page=N`)을 본다. N은 사이트 화면에서 사이트별로 정한다(1~10, 기본 3). 2쪽 이후를 못 읽어도 실패로 치지 않는다.
- 제목에 프로그램 이름의 모든 단어가 들어 있고(대소문자 무시) 선택한 해상도 중 하나라도 제목에 있으면 매칭이다. 무관이면 해상도를 보지 않는다. 여러 프로그램이 맞으면 목록 순서상 첫 번째가 이긴다.
- 회차 키는 제목의 `E823.261011` 형식(날짜가 없으면 `E12`)이다.
- 같은 해시나 같은 (프로그램, 회차)는 한 번만 추가한다. 같은 회차가 여러 사이트에 올라와도 하나만 받는다. 회차 키가 없는 글은 해시로만 중복을 막는다.
- 사이트 첫 게시판이 실패하거나 글이 0개면 도메인 번호를 +1..+5까지 바꿔 보고, 글이 나오는 도메인으로 사이트 URL을 갱신한다.
- 같은 사이트(호스트)에 연달아 요청할 때는 2~5초 무작위로 쉬고 요청한다. Doctor 도구 요청도 같다.
- 이미지·폰트·미디어 요청은 막는다(사이트 부하와 크롤링 시간 절감). CSS와 JS는 그대로 받는다.
- 상태: 모두 성공이면 `ok`, 일부 실패면 `partial`, 성공한 사이트가 없으면 `error`.

## 실행 방식

- 대시보드에서 **수동** 또는 **자동**을 선택한다. 설정은 DB에 저장되어 서버 재시작 후에도 유지된다. 기본값은 수동이다.
- 수동에서는 **지금 실행** 버튼을 눌렀을 때만 크롤링한다. 자동에서는 설정한 주기(기본 60분, 5~1440분)마다 크롤링한다. 자동으로 전환하면 전환 시각부터 한 주기 뒤에 첫 실행을 예약한다. **지금 실행**은 어느 방식에서나 사용할 수 있으며, 자동 모드에서 수동으로 실행하면 다음 예약은 그 실행 시각을 기준으로 계산한다. 수동으로 전환하면 다음 예약은 취소된다.
- 자동·수동 선택은 크롤링 실행 방식만 바꾼다. 크롤링에서 발견한 새 마그넷과 직접 입력한 마그넷은 두 방식 모두 일시 정지 상태로 등록된다. 대시보드의 **재실행** 버튼을 눌러야 해당 토렌트의 다운로드가 시작된다.

## Doctor

| 판정 | 의미 |
|---|---|
| `ok` | 정상 |
| `domain_moved` | 도메인 이전 |
| `blocked` | 차단 |
| `site_down` | 사이트 다운 |
| `transient` | 일시 장애 (지금은 접속 안 되지만 최근 크롤링은 성공) |
| `cloudflare` | Cloudflare 사람 인증 필요 |
| `parser_broken` | 사이트는 정상인데 파서가 실패 |

- 설정된 첫 게시판에 Chromium으로 접속해 글 목록이 파싱되면 Claude 호출 없이 즉시 `ok`로 기록한다. 로그인 화면이나 빈 페이지는 성공으로 보지 않는다.
- 도구는 직접 만든 읽기 전용 4개뿐이다: `dns_tls_check`, `browse`, `run_parser`, `probe_domains`. 내장 WebFetch, Bash 등은 막는다(SNI 차단에 걸려 오판하기 때문).
- 모델은 별칭 `sonnet`(기본) 또는 `opus`로 지정해 항상 최신을 쓴다.
- 실행당 최대 15턴, 비용 상한 $1.
- `browse`는 연결 끊김(`ERR_CONNECTION_CLOSED`/`RESET`)이면 5·10·15초 간격으로 다시 시도한다. ECH 설정이 늦게 와서 잠깐 평문 SNI로 붙는 일시 실패를 차단으로 오판하지 않기 위해서다.
- 수정 제안은 자동 반영하지 않는다. 리포트의 [이 설정으로 변경] 버튼을 눌러야 사이트 설정이 바뀐다.
- Chromium은 크롤링과 Doctor가 lock을 공유해서 동시에 하나만 뜬다.

| `settings` | `run_mode`(기본 수동), `auto_enabled_at`, `interval_min`, `doctor_model` |
| `runs` | 실행 기록(상태, 매칭/추가 건수, 로그) |
| `run_list_hidden` | 대시보드에서 숨긴 완료 실행 ID. 실제 `runs`와 스케줄 기준은 유지 |
| `downloads` | 크롤러 또는 직접 입력으로 추가한 해시와 회차(중복 방지 기준) |
| `download_list_hidden` | 대시보드 이력에서만 숨긴 해시 |
| `doctor_reports` | 진단 리포트(판정, JSON, 비용, 진행 로그) |

새 DB를 만들 때 기본 사이트와 프로그램이 추가된다. 사이트를 모두 삭제해도 재시작만으로 기본 사이트가 다시 추가되지는 않는다.

- 사이트 5곳(초기 URL): 토렌트썸 `https://torrentsome270.com`, 토렌트좋다 `https://torrentzota208.com`, 토렌트티티 `https://torrenttt255.top`(이상 켬), 토렌트알지 `https://torrentrj276.com`, 토렌트밤 `https://torrentbam254.top`(이상 끔, 예비). 게시판은 사이트마다 예능·오락, 한국드라마, 다큐·교양 3개. 사이트 화면에서 새 사이트를 꺼진 상태로 추가하거나 삭제할 수 있다. 삭제 시 해당 사이트의 진단 기록도 삭제되지만 다운로드 이력은 유지된다. 모든 사이트를 삭제해도 재시작 시 기본 사이트가 다시 생기지 않는다. 실제 URL은 사이트 화면에서 수정할 수 있고 DB를 유지하는 재시작에서는 덮어쓰지 않는다. `reset`으로 새 DB를 만들면 이 초기 URL을 사용한다.
- 프로그램 17개. 놀면 뭐하니와 라디오스타만 켜져 있다.

## 악성 콘텐츠 제한

- 게시판의 글 링크는 해당 사이트와 같은 출처(HTTPS·호스트·포트)만 따라간다. 사이트가 예상하지 못한 도메인이나 HTTP로 리디렉션하면 게시판·상세 페이지를 성공으로 처리하지 않는다. 번호가 +1..+5인 후보 도메인만 자동 이전 대상으로 인정한다.
- 크롤링(자동·수동)과 직접 입력한 새 마그넷은 Transmission에 일시 정지 상태로 등록한다. 대시보드에서 항목을 확인하고 **재실행**을 눌러야 다운로드가 시작된다. 기존 Transmission 항목은 변경하지 않는다.
- 이는 사이트 이동과 외부 링크를 제한하는 규칙이며 악성코드 검사는 아니다. Transmission은 별도 Pi에서 실행되고 이 컨테이너에는 다운로드 파일이 마운트되지 않는다. RPC는 파일명과 상태를 제공하지만 파일 내용은 제공하지 않으므로, 현재 구성만으로 내려받은 파일의 악성코드 유무를 판정하거나 자동 격리할 수 없다. 파일 검사를 하려면 Pi에서 백신을 실행하거나 다운로드 폴더를 이 호스트에 읽기 전용으로 공유해야 한다.
